## 当前实现

主进程保持普通权限。用户点击启用后，ShellExecuteEx runas 启动同一已构建 exe 的限定 --storage-companion 模式；该分支在 Tauri/WebView 初始化前执行，不把浏览器界面提升为管理员。组件只连接启动者预先创建的本机管道，双方校验实际进程、用户/会话身份和一次性随机值，并检查存储协议版本。原有严格对端身份检查没有降级；UAC 分离令牌下是否匹配仍需实机确认，失败会退出并显示错误。

组件每次启动固定 --storage-companion-read 子进程，调用已验证的 PS_StorageCmdlets.GetStorageReliabilityCounter。子进程最长等待 10 秒、输出上限 64 KiB，超时回收自己的子进程。成功后间隔 5 秒再读；不安装驱动、服务、自启项，不启动 ETW，不写应用历史。停止按钮关闭通道，组件完成或超时当前查询后退出；主进程最多等待 15 秒确认组件结束，超时显示未成功停止。应用退出也请求停止；崩溃后的完整退出边界仍待验证。

普通权限源读取已实测：设备名称与健康可见，温度等权限受限字段为空，未以零替代。字段转换只新增一项必要测试：保留真实 Wear=0、PowerOnHours=null，拒绝 USB Temperature/TemperatureMax 同为 0 的无效读数。严格 Clippy、TypeScript 检查和 Windows Tauri 构建通过，没有重复扩大整个测试矩阵。

显示明确区分 Windows 健康状态与剩余寿命。当前增强卡片采用本次来源自己的磁盘名称/盘号，与旧吞吐卡片分开展示，尚未确认可持久化的跨进程设备身份，因此暂不写温度历史，也不凭盘号将增强值拼到旧历史。读数超过 20 秒显示过期并隐藏值；部分来源失败显示未知，可继续停止组件。
