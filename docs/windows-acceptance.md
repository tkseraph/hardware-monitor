### 原生窗口验证

上次构建已在隔离目录看到真实 CPU/RAM、进程表、禁用的存储排序/结束按钮与自启按钮；SQLite 确实写入 CPU、逐核和内存指标。2026-09-15 恢复工作时，该旧测试进程仍在运行，未重启或替换其可执行文件与数据目录；不能据此声称已经完成资源挂测或无泄漏证明。

新版使用单独的编译输出和全新隔离目录。原生窗口显示 Windows、12/24 核、55.62 GiB OS 内存与动态 CPU/RAM；GPU、存储明确显示未实现，没有零值曲线。WebView 数据、debug 日志和数据库属于该测试根，不读写旧实例的历史。

已取得的原生实测结果：

- 稳定前台段的 CPU 样本间隔为 1 秒；通过系统菜单执行最小化后，连续后台间隔为 3 秒；恢复后回到 1 秒。最初一次 UIA 点击未观察到后台状态，没有将该次操作当成有效最小化证据。
- 将前台间隔从 1000 ms 调到 1100 ms 后，界面显示保存成功，隔离目录中的 settings.json 确实为 1100。中断后重启相同隔离实例，界面恢复 1100；再调回 1000，已有设置文件成功覆盖。
- 使用设置页的“退出软件”结束本轮测试实例，确认对应主进程已退出；只读 SQLite integrity_check 返回 ok。未停止此前独立运行的旧实例。

## W5b 首批持久化修复

2026-09-16 在独立临时数据库和设置目录完成以下修复：历史预算由只检查主 DB 改为合计主 DB、WAL、SHM；大小读取失败返回 I/O 错误并停止新增历史，不视作零占用，也不误标为超预算。设置写入采用 create_new 独占临时文件，检查 write_all 与 sync_all，关闭句柄后替换目标；失败会保留原文件并尝试清理本次临时文件。

新增三项生产路径测试全部通过：WAL/SHM 使总占用超过注入预算时不插入新行；无法读取主库占用时拒绝写入；Windows 已有设置可覆盖，目标被独占打开时保存失败且旧文件内容不变。默认 Rust 测试合计 66 通过、8 个显式本机测试忽略，严格 Clippy 通过。

这仍是 W5b 的部分交付。当时待处理的后端 uniform stride 抽稀（后续进展见下节）、完整缺口元数据、500 ms 与秒级时间戳、真实七天运行，以及 W5a 的完整唤醒/自启/托盘恢复验证尚未完成。已有 W4 原生 UI 证据不会自动升级为本次全部 UI 重验。


## W5b 历史查询 v2（2026-09-16）
