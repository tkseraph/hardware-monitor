## 3. 问题清单

### F01 · P0 · 分层历史没有实现，清理会直接丢失一小时前的数据【确定】

- 位置：[history.rs:33](../../monitor-app/src-tauri/src/history.rs:33)、[history.rs:71](../../monitor-app/src-tauri/src/history.rs:71)、[history.rs:79](../../monitor-app/src-tauri/src/history.rs:79)、[lib.rs:110](../../monitor-app/src-tauri/src/lib.rs:110)。
- 10s/60s 桶只有建表，没有任何聚合写入；每小时清理直接删除一小时前的 raw 行；查询也仅访问 raw 表。
- 实际效果是清理后只剩最近一小时左右的原始数据，而不是 7 天；两次清理之间可能暂时积累更多。频繁重启则又可能延后清理，不能把偶尔看到旧数据当作留存保证。
- 修复：先保护现有数据；事务内先生成并核验聚合，再删除已被完整覆盖且符合保留策略的源行；查询按时间范围读取各档；增加迁移、备份、聚合幂等性与缺口元数据。
- 验收：可控时钟覆盖 1h/24h/7d 边界，故障中断或重复聚合不丢行、不重复计数；重启仍可查 7 天。

### F02 · P1 · 内存解析漏掉 wired 与压缩内存【确定】

- 位置：[lib.rs:238](../../monitor-app/src-tauri/src/lib.rs:238)、[lib.rs:260](../../monitor-app/src-tauri/src/lib.rs:260)。

- 修复：精确字段/冒号后数值解析，查询实际页大小；定义 app/wired/compressed/cached/free/available 的来源与去重口径，展示可解释分项，不为凑总量随意补差。
- 验收：多词字段、空格/句点变化、缺字段、零分母、不同页大小；与系统工具同时间窗口对照并记录差异。

## 4. 改进与优化原则

1. **先正确再快**：先修缺失值、错字段、错设备、错单位和留存，再减少进程启动、查询量及 UI 重绘。
2. **采集器归 Rust 管，页面只读快照**：一个来源一个状态/基线；慢来源不阻塞快来源；不为页面重复采样。
3. **观测时间≠写入时间≠刷新时间**：UTC 持久化、单调时间差分、实际覆盖区间/会话代次，绝不把旧值刷新当新采样。
4. **结构化与最小化读取**：普通权限原生 API 优先；保留系统命令时精确选项、定向节点、白名单环境、超时及输出限制。
5. **历史单写者+有界队列**：批量事务、可观测故障、按窗口/像素限制查询点数；查询不长时间持有采样锁。
6. **不盲目重构**：保留 Tauri/React/Rust/SQLite，先在现有 crate 抽 module；图表库是否引入取决于时间轴、缺口、无障碍等需求，不仅为了视觉效果。
7. **生产无模拟 fallback，测试允许隔离夹具**：固定测试数据明确只属于测试环境；原生采集仍需实机对照。
8. **不制造权限需求**：普通权限能读的 SMART 不升级为 root；传感器源未验证先报告，不自动安装 helper、调用 sudo 或关闭安全保护。
9. **优化以报告为准**：前台/后台全进程树 CPU、内存、磁盘写入、P50/P95 来源耗时与漏采率形成基线后，再决定缓存/原生化/降采样；不宣称当前已达资源预算。
