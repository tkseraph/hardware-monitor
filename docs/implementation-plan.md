日期：2026-09-11。状态：依据 D-012 仅调整计划，尚未开始开发；本次不运行采集探测、构建或应用测试。

产品约束以 [需求决策 D-001～D-012](requirements.md) 为准，平台顺序以 D-012 为准；概念与不变量见 [领域模型](domain-model.md)。本文的框架、调度细节、界面默认值和资源预算是工程建议，不冒充用户已经确认或实测达成的指标。

## 1. Mac 优先交付目标与当前操作边界

**本轮仅编辑计划文档。以下步骤均是后续获准开发时的路线，不是现在执行的任务。** 不创建代码、安装依赖、运行新增硬件探测、提权或注册采集组件。

当前交付目标只有用户本机：**Apple M4、macOS 26.5.2、arm64**。

- 总览、CPU、GPU、内存、磁盘详情和设置；四类硬件都有真实动态数据。
- 物理盘/容器/卷展示，进程内存与系统范围的进程存储读写排行。
- 设备级历史本地保存 7 天；关窗常驻 Mac 菜单栏继续采集，完全退出停止；主要动态指标前台/后台默认目标 1 秒/3 秒。
- 普通权限基础模式与可选的 Mac 增强采集分离；温度、通电时间、健康度等按实际能力及既定安全边界验证和接入。
- 包含历史、权限、退出/睡眠恢复、稳定性与资源验证，以及 Mac app/DMG 的安装、运行和卸载验收。
- 不做商店上架、自动更新、远程监控、云端历史、告警、超频、调速或按物理盘归因的进程读写。

“Mac 全部跑通”指完成已确认交付范围的整体验收，不是仅启动成功或只完成基础占用率原型。D-010 的分阶段及高级指标迭代方式保留；所有缺项必须如实列出，影响约定验收的偏差需处理或取得用户认可。

**Windows 延后，不与 Mac 并行开发，也不阻塞 Mac 交付。** 只保留既有设备资料、平台无关契约和适配边界；Mac 整体验收通过后，由用户再决定是否启动 Windows 扩展。

## 3. 推荐架构

### 3.1 技术组成

Tauri/React/Rust/SQLite 仍为工程建议，不因 Mac 优先而自动改换技术栈。当前只计划实现 Mac 所需部分；Windows 条目仅保留为未来候选，不创建空实现、不安装依赖、不推进选型验证。

| 层 | 建议 | 理由与边界 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | 复用 macOS/Windows 系统 WebView，提供窗口、菜单栏/托盘、原生 IPC 和安装打包；并不自动保证低资源占用 |
| 界面 | React + TypeScript，图表优先评估 ECharts | 统一页面与状态展示；图表只绘制当前窗口需要的分辨率，避免一次把 7 天原始数据塞入 WebView |
| 核心 | Rust | 统一指标语义、调度、差分、能力判断、历史与平台适配；不把所有功能绑定到某个采集库 |
| 基础采集库 | `sysinfo` 候选，按需刷新 | 用于 CPU、内存、进程及部分清单；必须核对每个平台字段的口径，不假设覆盖 GPU、SPD 或全部温度 |
| Windows 原生适配（延后） | Rust `windows` 绑定 + 系统性能/存储接口，仅作既有候选记录 | 当前不开发、不引入 Windows 专用依赖；后续启动时再核实 |
| macOS 原生适配 | Mach、sysctl、libproc、IOKit/Disk Arbitration 等 | 按数据类型隔离实现；静态设备名称与动态指标分开验证 |
| macOS 增强组件 | 小型 Swift 组件，优先评估 SMAppService + XPC | 用户授权的独立只读采集；`powermetrics` 可作为受控来源之一，不能让界面任意执行高权限命令 |
| Windows 增强组件（延后） | 独立服务、C#/.NET 与 LibreHardwareMonitorLib，仅作既有候选记录 | 当前不做组件或驱动接入；Mac 不依赖它们，未来重新核实许可、安全与设备收益 |
| 历史 | SQLite，由 Rust 单一写入队列管理 | 本地持久化、事务、时间范围查询；前端不直接访问数据库 |

本次读取的 `sysinfo` 文档版本为 0.39.6，LibreHardwareMonitor 官方最新发布接口返回 v0.9.6。它们只是研究候选，不是已审计、已锁定或已安装的依赖。实现时固定版本、生成锁文件和第三方声明，再做来源与安全检查。

### 3.2 数据流与信任边界

```text
React 界面（普通权限；无任意 shell、文件或网络能力）
        │ 受限且有类型校验的 Tauri IPC
        ▼
Rust 应用核心（普通权限）
        ├── 唯一调度器 → macOS 普通权限采集来源
        ├── 能力判断、差分、快照、订阅与拓扑
        ├── SQLite 写入/聚合/查询队列
        └── 经过身份校验的本机 IPC
                    ▼
             可选 macOS 只读增强组件（用户单独授权）
```

- 页面只请求快照、订阅、历史范围和经校验的设置，不能传任意命令、路径或驱动 IOCTL。
- 不启动对外 HTTP 采集服务，不加载远端网页脚本；配置 CSP 和最小 Tauri capabilities。
- Mac XPC 校验调用者身份/代码身份；仅有随机 token 或 localhost 地址不构成完整认证。Windows 命名管道/ACL 仅保留为后续扩展约束。
- 高权限组件不提供通用文件读写、进程控制、设备寄存器写入或硬件控制端点。
- 底层库即便同时支持监控和控制，也仅开放经过审查的监控路径；“只读产品”不能替代对底层初始化行为的检查。
- 应用与增强组件以会话/租约绑定；正常退出主动停采，控制进程崩溃时通过超时回收任务，避免孤立常驻采集。
- Mac 卸载与撤回增强授权需有独立流程；Windows 驱动卸载与共享驱动保护属于后续扩展约束。

### 3.3 候选工程布局

以下仅为未来 Mac 开发阶段的目录建议，本轮不创建这些目录或代码。Windows 目录不预先创建：

## 4. Mac 采集策略与关键验证（尚不执行）

完整状态见 [能力矩阵](capability-matrix.md)。后续 Mac M0 优先验证：

1. **M4 GPU 利用率与整机内存统计**：普通权限 IOKit 等来源优先，必要时在单独授权后验证 `powermetrics`。统一内存容量、建议工作集和进程分配量不是同一个指标；没有正确分母就不显示虚假显存百分比。
2. **CPU 与内存**：确认总/每逻辑处理器占用差分、P/E 核心映射以及内存各字段口径。已知 P/E 数量不能替代逐核心映射证据；首个差分样本显示预热。
3. **Mac 进程存储 I/O**：验证 libproc/rusage 等来源的权限范围、累计计数、差分窗口及存储含义；不按盘归因，不采集文件内容或实际访问路径。
4. **两块 SSD 与 APFS**：建立物理盘、容器、卷和容量资源池关系，验证物理盘吞吐；不重复累计共享空间或卷级计数。
5. **温度、通电与健康**：逐一验证 CPU/GPU/存储传感器与 SMART/NVMe 字段；thermal pressure 不是摄氏温度，SMART Verified 不是寿命百分比。可选风扇监控只报告经过验证的读数。
6. **Mac 增强组件**：评估独立授权、身份校验、受控采集、停用/退出与签名安装，不关闭 SIP 或其他安全保护。

Windows 的 GPU、进程 I/O、传感器和驱动问题不进入 Mac M0，保留在后续扩展备忘中。

## 5. 建议的工程默认值

这些是可调整的实现建议，非额外用户承诺。

### 5.1 页面与指标口径

- 简体中文，默认跟随系统浅色/深色；左侧导航，总览采用可响应的硬件卡片，详情统一包含核心读数、曲线、细分字段和来源/权限说明。
- 多 GPU、多物理盘按设备实例展示，不写死只有一个 GPU 或一块 SSD。
- 磁盘按“物理盘 → 关联容器/卷”组织，复杂多对多关系明确标注；隐藏辅助卷不能造成容量失真。
- CPU 总量按逻辑计算容量归一到 0–100%；每逻辑处理器独立 0–100%，物理核/集群聚合方法必须有来源依据。
- Mac 若得到 GPU 活跃驻留比则明确标注方法；Windows 的最忙引擎等口径留待扩展时核实，不作为 Mac 展示或验收依赖。
- GPU 专用、预留、共享和统一内存分开表达；预算不是物理容量；共享 RAM 不重复加总。
- 系统内存保留安装量、系统可使用总量、当前已用、可用、空闲等独立概念；按平台明确公式，不能强迫压缩内存、缓存等分类跨平台完全一致。
- 容量显示 GiB/TiB 或显式选择十进制 GB/TB；吞吐若标 MB/s，分母为 1,000,000 字节；MT/s 不写成 MHz。
- 不可用字段给出原因和实际操作建议；未实现、未验证与设备不支持分开。过期值展示上次时间，不使用 0 或动画掩饰。

### 5.2 进程明细

- 首版保证可排序、可搜索的真实进程表，展示 PID、名称和明确口径的内存/存储读写字段；受限或已退出进程单独处理。
- 可可靠识别应用身份时再做应用分组并允许展开；不根据相同名称盲目合并，也不把未去重的共享内存求和当作应用物理占用。
- 建议相关详情可见时每 2 秒更新；不查看时暂停额外进程明细枚举，整机/设备历史仍按既定策略继续。
- 不默认保存进程明细历史，不读环境变量、命令行、文件内容或实际读写路径；诊断报告进一步脱敏。

### 5.3 调度与历史

- 主要动态指标使用已确认的前台 1 秒、后台 3 秒目标；传感器 2–5 秒，健康/通电约 60 秒，静态信息启动或变化时读取。
- 一个底层来源只由一个任务负责，多个页面共享；不为每个指标/页面重复启动系统工具。
- 候选历史档位：最近 1 小时保留原始有效样本；1–24 小时使用 10 秒桶；1–7 天使用 60 秒桶。不制造比原始采样更精细的数据。
- 桶保存有效覆盖时长、极值及适用的时间加权平均；吞吐还可保存区间字节量。聚合规则按指标类型定义，不无差别求平均。
- 缺口是独立信息；不能因一个聚合桶存在少数样本就把整桶画成完整观测。
- SQLite 候选 WAL、单写入者、批量事务和受限队列；进程明细不进入设备历史表。数据库忙、损坏、磁盘满时展示记录故障，不让 UI 或基础采集被阻塞。
- 7 天过期清理与 schema 迁移可测试、可恢复；原有历史有备份/恢复策略，不遇到迁移错误就静默删除。

### 5.4 资源观察目标

后续只先在本机 Mac 实测；本轮不执行测试。以下仅作为优化起点，Windows 不作为达标前置条件：

- 稳态整机归一化 CPU：前台平均不超过 2%，后台平均不超过 1%；分开记录基础与增强模式。
- 应用、WebView、子进程和增强组件一并计入内存，初始观察阈值 250 MiB；同时记录平台私有/footprint 指标，说明 RSS/工作集求和可能重复共享页。
- 7 天历史与 WAL 初始软预算 512 MiB；超标先分析、压缩或调整较旧数据粒度，不擅自删除约定保留期内的历史。
- 不阻止睡眠；关窗停止图表动画，完全退出后停采。资源测试至少包含空闲、交互、增强采集和多盘变化。

### “Mac 全部跑通”的验收门槛

- M1 是内部原型，不是平台完成标志；实时采集、页面、进程、历史、菜单栏/生命周期、权限、稳定性和安装验收缺一不可。
- D-001 的能力降级与 D-010 的分阶段安排仍有效，不承诺硬件未开放的指标；原始清单不删除，所有缺项和后续迭代项在 Mac 验收报告中明确列出。
- 基础目标不可用、约定功能未完成或验收偏差未处理时，不能通过把字段标成“不支持”来宣布 Mac 完成。
- Windows 不得与未完成的 Mac 约定范围并行推进；通过 Mac 验收也不等于自动获准开发 Windows。

### 后续获准开发时的 Mac M0 顺序

1. 定义本机脱敏报告格式，包含来源、权限、环境、样本时间、状态和验证证据。
2. 验证 CPU/内存、物理盘吞吐和 APFS 拓扑，再优先验证 GPU 全局指标。
3. 验证进程内存和系统范围的进程存储读写；不把错误范围的数据改名使用。
4. 如需增强，在解释来源和影响后单独请求实际授权，限制采样时长；不自动调用 sudo 或安装永久服务。
5. 对照系统工具与获准的小规模可控负载；不自动进行满载、磁盘压力写入或广泛文件扫描。
6. 更新 Mac 能力矩阵，报告关键阻碍，再确定实际采集来源。没有 Windows 探测任务。

- 增强组件的 bundle、SMAppService 注册、签名/调用者身份校验需单独验证。
- 自用不默认需要商店上架；签名、公证与实际安装限制仍需评估。账号/证书有缺口时先报告，不自行购买或关闭系统保护。
- 安装运行应脱离开发命令；卸载应正确清理自身组件，不以直接删应用图标替代增强组件的生命周期设计。
- 实际实现后按版本记录依赖/许可并锁定来源；当前的资料研究不构成依赖安全批准。
- 当前不设置 Windows 构建目标、构建机或 CI，不上传仓库、不购买云服务；Windows 不构成 Mac 构建/安装前提。
