# Windows GPU 边缘温度与历史（2026-09-30）

本机 Radeon 890M 已接通自动读取、实时显示和温度历史。图形处理器详情新增“GPU 边缘温度”和最近一小时曲线，沿用原有 GPU 历史连接选择器。主界面与采集进程保持普通权限，没有新增 UAC、驱动或服务。桌面快捷方式指向的开发构建已更新。

## 读取与交付方案

复用本机已有 ADLX 1.5.0.124 运行库；首次来源验证所用的 C++ SDK 不参与产品构建或打包。AMD 官方 Samples/rust/amd-adlx 子目录有明确独立 MIT 声明，本次仅改编它的必要只读虚表前缀，不导入完整 SDK、调节接口或供应商二进制。[上游许可](https://github.com/GPUOpen-LibrariesAndSDKs/ADLX/blob/32b5a740d42295c5dfe9026b9f52683da0f3af91/Samples/rust/amd-adlx/LICENSE)。来源锁定提交 32b5a740d42295c5dfe9026b9f52683da0f3af91，声明保存在 docs/licenses/amd-adlx-rust-MIT.txt；Windows 资源配置已包含该文件，开发构建中已核对实际副本。这不将其他 SDK 材料推定为 MIT，也不替项目选择整体许可证。

读取只从固定 System32 路径加载已审核的 amdadlx64.dll，核对完整 SHA-256 和 ADLX 版本。校验至所有调用结束期间持有不允许写入/删除共享的文件句柄。当前白名单只支持本机已核验的驱动构建，驱动更新后显示来源未核验；不加载工作目录中的同名 DLL、不静默接受新版本。

同一 app.exe 的 --gpu-temperature-read 模式在 Tauri 初始化之前执行，只获取 GPU 清单、LUID、温度支持标志与当前边缘温度；不设置采样跟踪、不读取文件路径、不调用调频/风扇/功耗控制。所有接口引用先释放，再 ADLXTerminate 和卸载运行库。

来源工作线程持有本轮 DXGI 工厂、适配器及匿名系列，前后校验工厂仍有效、LUID 与现有 UID 对应。设备型号不是关联键。独立子进程受自己的 Windows Job Object 管理，句柄关闭即终止自身子进程；每次等待上限 3 秒、输出上限 32 KiB，超时/停止会请求结束。旧子进程与输出读取线程未结束时，不启动替代采集，以保持数量有界。实际驱动挂起和运行中崩溃未在本轮模拟。

## 历史与显示

新增明确指标 gpu.temperature.edge，单位 °C，与磁盘温度及 GPU 利用率分开。有效新读数才由已有有界历史线程写 SQLite；无读数/来源失败不写零值。前台最短周期 2 秒，后台沿设置的更长周期运行。来源失败、丢写、时间连续性变化或温度对象集合变化会分段。快照仅将温度附到相同匿名 UID 的当前 GPU，过期或其他系列的数据不作为实时值显示。

本轮曾评估旧 ADL 接口作为另一条路径；驱动为同一 GPU 提供多个显示条目，PMLog 边缘字段不支持，OverdriveN 返回 -8。因此没有把这些返回的零值作为温度接入，也没有依赖显示条目猜配。这一结果只限制该读取路径，ADLX 已实际返回温度。最终产品源为上述 MIT Rust 绑定的 ADLX 路径。

## 一次集成检查结果

类型检查、严格 Clippy 与 Windows Tauri 构建通过，没有新增单元测试或重跑全套测试。普通权限启动隔离实例后，界面实际显示 59°C、之后更新为 60°C，并直接观察到温度曲线。最终 SQLite 保存同一 GPU 的 99 个真实样本，范围 52–62°C，首末覆盖 201 秒，与 GPU 注册表 UID 相符，未保存无效零温度。

记录分为 57 和 42 个样本的两段，最大记录间隔 6 秒，缺测没有伪装成连续采样。之后通过设置退出该测试实例，已确认主进程及其 app 子进程全部退出，日志未出现来源工作线程退出超时。该结果不是长期稳定性或独立传感器校准。
