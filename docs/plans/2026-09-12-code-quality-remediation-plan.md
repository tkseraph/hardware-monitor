## 1. 贯穿所有阶段的约束

1. 禁止执行系统休眠、计划休眠、唤醒测试或修改电源设置。用虚拟时钟与事件注入验证暂停/恢复。
2. 不使用 sudo、不安装 helper/驱动、不注册登录项、不改 `/Applications`。确需真实登录项验收时另获用户明确授权。
3. 进程操作保持 D-013：普通权限、SIGTERM、二次确认。测试仅对专用子进程发信号，禁止结束真实应用、远控、挂测实例。
4. 不删除真实历史、不在真库注入合成数据。任何迁移先用 SQLite 一致性备份（包括 WAL 状态），在副本验证后才考虑切换；不能只复制正在写入的 `.db` 主文件。
5. 生产 UI 不显示假数据。模拟、错误注入和虚拟时间仅用于测试，验证页必须明确标识，不能进入 release。
6. 不记录/上传序列号、UUID、用户目录、主机名、命令行、访问路径；诊断使用允许字段白名单。真实报告的删除/历史改写另获授权。
7. 保持 ad-hoc 本地签名。Developer ID/公证、CPU/GPU 核心温度增强均维持暂缓；不改变 SIP 等系统保护。
8. 每阶段独立分支/提交，先写失败用例再修复，阶段通过后才合并。实施前固定仓库级匿名 Git 身份，不能用自动推断的本机身份提交。
9. 每次可预览 UI 改动使用浏览器文本/样式/交互工具验证并给证据；涉及 Tauri/本机权限的部分单独说明原生验证状态，不以浏览器模拟代替。
10. 不自动推送、重写远程历史或启用会上传本机诊断的 CI。版本/平台/许可证扩展需要明确决策。
