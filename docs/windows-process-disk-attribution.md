# E3 进程磁盘 I/O 归属计算模块

更新：2026-09-24。实现位于 `monitor-app/src-tauri/src/enhanced/disk_io.rs`，作为 E3 的计算基础，不表示真实 ETW 进程排行已经接通。

## 已实现行为

输入是经原生适配器验证后的进程/线程生命周期、磁盘请求发起和完成事件，以及单调时间（纳秒）。模块自身不读取系统、不启动 ETW、不请求管理员权限、不生成文件负载，不向界面或历史数据库注入模拟值。

- 进程身份由 PID 与可靠创建标记组成。线程映射到这个身份，磁盘请求在发起时捕获所属进程；不使用完成回调恰好运行的进程来猜归属。
- 请求完成前进程退出或 PID/TID 被复用，已捕获的请求仍属于旧进程。新进程不能继承旧字节数。退出和新出现进程的部分窗口保留字节诊断，但速率返回未知。
- 同一请求标识在未完成时复用视为关联歧义，丢事件、乱序或容量越界也使当前采集基线失效；必须显式重建经过验证的基线，不能仅推进时间窗口后恢复有效状态。
- 完成事件缺少发起关联或方向不符时，累计未归属操作/字节，窗口标为不完整，不按 PID 或相近时间猜配。未归属字节仅作诊断，不并入某个进程。
- 使用实际窗口时长计算 B/s。只有完整观测窗口内一直存在的进程才允许显示有效零；新进程、已退出进程和不完整窗口的速率为空。
- 跨窗口请求保留关联，字节计入完成时间所在窗口；窗口边界语义为 (start, end]。100 ms 以下、15 秒以上或倒序的窗口无有效速率，并清除旧基线。后续原生适配器需按约一秒固定聚合，不依赖进程页面何时刷新。
- 默认上限：4096 个进程、65536 个线程、16384 个未完成请求、4096 行窗口统计。超过上限显式标记不完整，不把截断结果当完整排行榜。
- 未完成请求在窗口维护时保留最多 60 秒；超时清理会使基线失效并累计过期数。迟到完成事件不能恢复旧关联。这是保守保护，不表示真实磁盘请求绝不可能超过 60 秒。

窗口里的 read_bytes/write_bytes 是本窗口内已归属字节，不是进程启动以来累计值，不能直接覆盖旧 ProcessInfo 的累计字段。创建标记在未来 IPC 中仍须转为十进制字符串，不能让 JavaScript Number 丢失精度。

## 接下来接入真实数据的门槛

1. 原生 ETW 适配器需要解码磁盘发起/完成事件，以及进程/线程生命周期；按事件版本和指针宽度验证字段，转换 QPC 为纳秒，不能猜定字节偏移。
2. 建立可靠的启动基线、事件排序与枚举期间的交接流程。这里的 baseline_complete 是调用者履行验证后的承诺，不能在收到零散事件后直接调用。不能从进程名或低精度创建时间构造身份。
3. 检查真实事件中请求关联键的适用范围、重复/迟到事件语义，加入每个事件的丢失诊断。现有五秒探针只计数，没有读取这些字段，不能借其成功替代本阶段验证。
4. 设计完整窗口的有界分块传输，解决 E1 协议当前 256 行上限；只有收到同一快照的完整分块后才能发布，不能先截前 256 行再排序。
5. 将已验证速率按 PID＋创建标记合并到现有进程表，并保留未知/不完整状态。温度、ETW 和基础采样故障应独立。
6. 准备限定临时文件大小的自建测试进程与同窗口独立计数器对照，再申请具体的单次管理员运行。此前磁盘读取或事件计数探针的单次授权不能自动覆盖新的事件归属实验。

本文件记录的是归属计算模块的完成情况。真实进程磁盘排行、持续运行的授权采集组件、温度界面集成、服务或驱动安装都尚未完成。


## E3 原生事件解码增量（2026-09-24）

新增 enhanced/etw_decode.rs，使用 TDH 按字段名读取，不用硬编码 payload 偏移。只读取磁盘请求标识、发起线程、完成字节，以及进程/线程编号；不读取文件名、命令行、用户 SID、栈地址等属性。底层 IRP 仅作内存关联键，不设计序列化或日志输出接口。

初始白名单为 Disk v3、Process v2–v4、Thread v2/v3 的指定事件；其他版本明确拒绝，不能猜测布局。32/64 位指针宽度以事件头标记为准，两种标记冲突或缺失时拒绝相关事件。TDH 返回宽度不匹配、属性缺失、无效请求标识时也拒绝；无关 provider/opcode 则忽略，不调用属性读取。

磁盘 ReadInit/WriteInit 转为 Begin，Read/Write 转为 Complete，不使用完成事件头 PID 归属。生命周期保留 Start、End、PresentAtStart 和 PresentAtEnd 四种语义；DCEnd 是会话结束清单，不是对象退出。ProcessId 本身也不作为可靠身份，尚需原生适配器通过有效句柄核实创建时间；不把内核 UniqueProcessKey 当作 FILETIME 创建标记。

转换使用固定会话 QPC 频率和原点，以整数运算生成相对纳秒。调用者必须显式设置 ClientContext=1 与 PROCESS_TRACE_MODE_RAW_TIMESTAMP；不能把默认转换为系统时间的 ETW 时间戳当 QPC。负差、零频率及溢出均拒绝。未在旧 E2 计数探针上自动打开新事件类别或解码。

新增五项常规测试覆盖字段宽度、请求标识、生命周期枚举语义、未知版本/字段、QPC 边界，以及解码到现有生产归属模块的端到端合成路径。另有显式 Windows TDH 合成事件测试，真实调用 TdhGetPropertySize/TdhGetProperty 并成功解码 64 位 Disk v3 完成事件；它不启动 ETW、不要求管理员权限，也不表示真实事件流已经通过。

本轮默认 Rust 108 通过、0 失败、9 忽略（增加一项显式 TDH 测试）；该 TDH 测试另行执行通过。严格 Clippy、格式与原生 debug 构建通过。当前只有磁盘事件可送入归属计算；生命周期只完成结构化解码，还未实现创建时间核验、启动基线交接、缓冲区内/跨缓冲区排序、丢事件联动以及完整快照传输。因此应用内进程磁盘排行仍不可用，未宣称 E3 整体完成。

文档依据：[DiskIo 起始事件](https://learn.microsoft.com/en-us/windows/win32/etw/diskio-typegroup2)、[Thread 生命周期](https://learn.microsoft.com/en-us/windows/win32/etw/thread-v2-typegroup1)、[Process 生命周期](https://learn.microsoft.com/en-us/windows/win32/etw/process-v2-typegroup1)。


## 身份、排序和限定范围基线（2026-09-24）

新增 identity.rs、event_order.rs、baseline.rs，尚未启动全系统实时 ETW 管线。

identity.rs 通过只读 OpenProcess/OpenThread 句柄读取创建/退出时间，以 GetProcessIdOfThread 核对线程所属进程。句柄由 OwnedHandle 持有到对象释放。旧线程不能与创建时间更晚、恰好复用 PID 的进程拼接；给定事件时间区间必须整体落在对象生命周期内，否则返回未知。原生自测只针对当前测试进程和线程，没有枚举其他应用或执行进程操作。

身份时间参数显式为 FILETIME 区间，解码器的 at_ns 仍为相对 QPC 纳秒。调用方必须提供经过校验的时钟映射与误差区间，不能把两者直接互传。本次尚未实现该动态映射及系统时钟跳变后的重建逻辑，因此不能宣称所有真实生命周期事件已经能安全归属。

OrderedEvents 使用容量受限的时间/到达序号索引，在调用方给定的水位线之前按时间交付。同时间戳保持到达顺序，不猜测并发事件先后。水位线回退、已交付边界之前的迟到事件和缓存超限均使队列失效，必须显式重置。原生协调层还需将这种错误同步为 Accumulator 的丢失/失效状态；不能捕获错误后继续发布正常窗口。水位线应来自延迟后的同一单调时钟，实际缓冲延迟与排序策略仍需实测。

baseline::install 只接受调用方已经持有的进程/线程句柄集合：先使旧速率失效，检查容量、唯一 PID/TID、线程所属关系和整个时间区间，再构建新基线并建立队列分界。所有检查成功才发布新基线，不会留下半组映射。它验证的是给定集合，不验证调用方是否枚举了全系统；不能把只含测试进程的集合标成系统完整覆盖。

新增 7 项测试覆盖实际当前进程/线程句柄、创建时间区间、乱序发起/完成送入生产速率模块、同时间戳、迟到/溢出/水位线回退，以及基线成功交接和重复身份拒绝。默认 Rust 测试 115 通过、0 失败、9 忽略；严格 Clippy、格式和原生 debug 构建通过。没有再次使用管理员授权，桌面快捷方式所指的构建未被替换。

下一项实际集成工作：全系统进程/线程枚举的覆盖说明、QPC/FILETIME 校准、枚举期间事件捕获与基线切换、生命周期动态应用和排序错误传播。随后才能准备新的有界管理员归属实验，以及完整快照分块到进程界面。E3 仍未整体完成。


## 时钟映射与系统枚举候选（2026-09-24）

新增 clock_bridge.rs 与 enumeration.rs，以及显式运行的 examples/enhanced_baseline_check.rs。主界面和增强采集会话尚未自动调用这些模块。

HostClock 在同一组 QPC 前后读数之间读取精确 FILETIME，生成时间区间而非假定两个时钟完全同步。单次校准跨度超过 5 ms、校准逆序、映射距离超过 5 秒或系统时间偏移超出预期范围时拒绝映射；后续校准失败使旧桥失效，须重新建立时钟与基线。当前使用 1 ms 的保守保护余量，它是实现策略，不是对所有 Windows 设备误差的测量承诺。原生适配器仍须定期校准、传播错误并清理旧 QPC 世代的数据；跨越未观察到的时钟跳变不能宣称无误差。

系统枚举通过 Toolhelp 同时取得进程与线程快照，只使用编号，不输出名称、命令行或镜像路径。随后打开只读句柄，核对线程与快照中的所属进程、创建标记以及整个枚举区间的有效生命周期。保护进程、权限失败、退出/重建和关联不符都计入 unavailable，不按默认值伪造身份。

枚举受现有进程/线程数量上限约束，并在循环与最终验证中检查 4 秒期限；超限/超时返回失败，不把截断集合标成完整结果。期限检查不能抢占单个阻塞 Windows 调用，生产部署仍需在已有子进程监督边界内运行。所有快照及身份句柄由 Rust 所有权回收。

本机普通权限实测：processes_seen=410、processes_verified=246、processes_unavailable=163、idle_excluded=1；threads_seen=10866、threads_verified=7933、threads_unavailable=2933；capture_ms=275。已验证集合成功进入基线安装流程，但 lifecycle_handoff_verified=false、systemwide_stream_ready=false。例程没有启动 ETW，未修改应用历史，执行后进程已退出。这些数量是当次快照，不是设备固定配置。

新增 4 项测试覆盖时钟区间和舍入、偏移/倒退/慢校准拒绝、真实当前进程的时钟及身份核验、枚举数量与期限拒绝。默认 Rust 119 通过、0 失败、9 忽略；严格 Clippy、格式及原生 debug 构建通过。

此步补齐系统枚举候选与时钟映射，尚未实现边采集 ETW 边枚举的无遗漏交接、生命周期事件的持续应用和完整窗口传输。候选集合不表示全系统覆盖，尤其不能用上述普通权限结果直接启用完整进程磁盘排行。下一步需要把实时事件缓存、校准、排序水位与基线切换组织成同一个受监督采集循环，并先准备只作用于自建测试进程的验证入口。


## 采集协调状态机（2026-09-24）

新增 pipeline.rs，将有界事件排序、基线安装和归属窗口连接为 AwaitingBaseline/Collecting/Ready/Invalid/Stopped 状态。每次重建产生新 generation，事件和异步错误均须带该编号；旧会话回调被拒绝且不能使新会话失效。Stopped 状态不能重新启动。

Collecting 期间缓冲事件。如果枚举区间观察到真实进程/线程 Start/End，则拒绝该候选基线，避免枚举与事件交接遗漏。成功交接只移除切换点及以前的事件，保留切换点以后的缓存数据并按时间处理。范围始终标为 verified_subset_only，未把普通权限枚举升级成系统完整覆盖。

排序迟到/超限、解码错误、事件丢失、时钟故障和不完整窗口统一撤销可发布速率。真实生命周期变化目前采用保守的请求重建处理，而非猜测新增进程身份；在频繁启动/退出程序的机器上可能导致连续重建，所以这一策略是验证阶段保护，不能作为 E3 已完整交付的依据。PresentAtStart/PresentAtEnd 清单事件不误当成退出。

新增四项集成测试覆盖切换后缓存保留、扫描期生命周期竞争、故障传播/旧回调隔离/停止以及未知完成事件不发布有效零。默认 Rust 整组测试 123 通过、0 失败、9 忽略；补强旧轮次异步错误隔离后四项状态机测试再次通过。格式、严格 Clippy 与原生 debug 构建通过。

显式普通权限例程 enhanced_baseline_check 已改为走 Pipeline：capture_ms=133；processes_seen=410、verified=247、unavailable=162、idle_excluded=1；threads_seen=10818、verified=7965、unavailable=2853；verified_scope_installed=true、pipeline_stopped=true、systemwide_stream_ready=false。无 ETW 会话、无管理员运行、无模拟读数进入产品。

剩余接入点：Windows ETW 回调和丢失计数实际调用 enqueue/report_fault；在同一监督循环中定期校准、选择排序水位并捕获枚举期间事件；为真实生命周期变化提供安全的增量身份解析或可用的重建策略；对自建进程执行限定负载的授权归属验证；再完成有界分块快照和界面合并。当前仍未启用进程磁盘排行。
