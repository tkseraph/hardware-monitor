## 采集与退出

用户启用时，复用既有受控 runas 启动方式，启动同一 app.exe 的 --cpu-companion 模式。该分支在 Tauri/WebView 初始化前执行；CPU 组件与磁盘组件使用各自限定协议，不能通过请求切换指标或执行任意命令。复用已实测的本机命名管道对端 PID/创建标记、SID/会话及系统配对 UAC 身份检查，再验证随机值与协议版本。CPU 协议四处共用同一 VERSION 常量。

组件仅运行固定 --cpu-companion-read 子进程，沿前阶段已核验的驱动/模块/CPU 型号和单物理包限制读取 Tctl。复用有界 Job Object 读取监督：每次最多 3 秒、32 KiB；旧子进程和输出线程未退出时不创建替代实例。CPU 前台在每次返回后间隔 2 秒再读，隐藏到托盘后间隔 5 秒。读失败不会刷新旧值，也不会写零温度。

停止按钮关闭主进程通道、撤销当前值，组件完成或超时当前读取后退出。主进程最长等待 15 秒确认退出；应用退出也请求停止。已安装的共享 PawnIO 驱动保留，不停止或卸载它。本轮没有新安装、重新配置安全策略或启动 ETW；崩溃/驱动挂起的完整边界未新增实机测试。

## 身份与历史

新指标 cpu.temperature.tctl，单位 °C，绑定 CPU 温度的匿名系列。收到读数后检查字段、当前单一目标 CPU 的名称与基本缓存一致；只有来源成功和身份确认时保存。每个软件启动建立新系列，不凭同型号推断重启前后是同一物理 CPU；同次启动的停止/重新启用保留同一系列，但使用新采集会话并分段。

cpu-temperature-series.json 保存可选择的旧系列，限制为 128 KiB、512 条，原子替换。注册表损坏、容量或保存失败时继续显示有效实时值，记录保存失败计数，不覆盖未知注册表。历史写入继续使用一个固定有界线程和容量 8 的队列；CPU 与磁盘各自保持连续性状态，交错采集不会重置对方的连续段。停止后图表仍可从 SQLite 读取。
